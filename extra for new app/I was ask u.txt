## 1. REFINED STORAGE FOOTPRINT (THE MATHEMATICAL CORRECTION)

In PostgreSQL, database size is computed using `pg_total_relation_size()`, which counts:
1. **Heap Size (Raw Data pages)**
2. **TOAST Tables (for large variable fields)**
3. **Index Sizes (B-Trees for primary keys, foreign keys, and unique constraints)**
4. **Alignment padding (bytes padded for memory alignment)**

Here are the actual measurements from the live production database (`jbjtvosvwufimjcvvwcg`):

### Table-by-Table Footprint Analysis

#### A. `auth.users` Table
- **Total size (with indexes):** 312 kB
- **Total rows:** 120
- **Actual average size per user:** `312 kB / 120` = **2.60 kB**

#### B. `public.users` Table
- **Total size (with indexes):** 152 kB
- **Total rows:** 117
- **Actual average size per user:** `152 kB / 117` = **1.30 kB**

#### C. `auth.identities` Table
- **Total size (with indexes):** 136 kB
- **Total rows:** 124
- **Actual average size per user:** `136 kB / 124` = **1.10 kB**
